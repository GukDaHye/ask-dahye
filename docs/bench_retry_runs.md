# 재시도 정책 전후 실측 기록 — `scripts/bench_retry.py`

README와 이력서에 쓰는 "실패 시 대체 응답 도달 시간" 수치의 근거다.
단일 실행값을 고정 수치처럼 쓰면 재현했을 때 어긋나므로, 실행을 모아 범위와 중앙값으로 남긴다.

## 측정 방법

존재하지 않는 모델명(`model-does-not-exist`)으로 호출해 **확정된 실패(404)** 를 만든 뒤,
두 재시도 정책에서 대체 응답까지 걸리는 시간을 같은 조건에서 잰다.

- **수정 전** — `APIStatusError`를 전부 재시도. 4xx도 대상이라 `RETRY_DELAYS = (1, 2, 4)`를 다 기다린다.
- **수정 후** — "다시 호출하면 결과가 달라질 수 있는가"로 판정. 4xx는 즉시 실패시킨다.

## 값을 어떻게 읽어야 하는가

**개선의 실체는 고정 대기 7초(1+2+4)를 제거한 것이다.** 이 부분은 실행과 무관하게 일정하다.

나머지는 OpenAI API 왕복 지연이라 실행마다 달라진다. "수정 전"에서 7초를 뺀 값이 왕복 4회분이다.

| 회차 | 수정 전 − 7초 (왕복 4회) | 수정 후 (왕복 1회) |
|-----:|------------------------:|------------------:|
| 1 | 1.70초 | 0.22초 |
| 2 | 2.24초 | 0.52초 |
| 3 | 3.99초 | 0.66초 |
| 4 | 1.38초 | 0.71초 |
| 5 | 0.94초 | 0.19초 |
| 6 | 0.92초 | 0.16초 |

왕복 지연 자체가 실행마다 4배 넘게 흔들린다(0.92 ~ 3.99초). 3회차는 양쪽 다 높고 5·6회차는 양쪽 다 낮지만,
4회차처럼 어긋나는 경우도 있어 두 열이 항상 같이 움직이지는 않는다. 표본 6회로 왕복 지연의 분포를 말하기는 이르다.
확실한 것은 **7초가 정책에서 오고 나머지가 네트워크에서 온다**는 구분뿐이다.

따라서 문서에 쓸 때는 **단일 값이 아니라 중앙값 또는 범위**로 쓰고,
7초가 구조적으로 제거된 부분이라는 점을 함께 적는다.

> 실패 시 대체 응답 도달: **8.54초 → 0.37초** (6회 실측 중앙값)
> 고정 대기 7초 제거, 잔여는 API 왕복 지연

## 재현

```
.venv/bin/python scripts/bench_retry.py
```
